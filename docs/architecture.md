# NanoSilicon CPU architecture 

## Overview 
NanoSilicon is a custom 8-bit CPU designed and implemented in Verilog HDL. Its processor, named JH-8, is built from individual hardware modules that work together to fetch, decode and execute a instructions. 

The design uses a modular architecture that consists of: 
- An instruction decoder
- An arithmetic logic unit (ALU)
- A four-register general-purpose register file
- A program counter
- Instruction ROM
- Data RAM 
- A processor status flag register 
- Central CPU control and datapath logic 

The CPU has an 8 bit instruction and data path, a 4 bit opcode field and a 2 bit register addressing scheme. 

## Top level architecture 

The main processor integration module is in jh8_cpu.v

It connects the individual hardware modules and coordinates instructione execution. 

The main data and control paths are: 
1. The program counter supplies the address to the instruction ROM.
2. The ROM then supplies the curent instruction and its immediate data. 
3. The instruction decoder extracts the opcode, destination register, source register and instruction length. 
4. The register file supplies two operands to ALU. 
5. The ALU performs the selected operation and generates status information. 
6. The writeback logic selects the value to be written into the destination register. 
7. The program counter sleects either hte next sequential address or a jump target. 
8. The flags module stores the processor's zero, carry and negative status flags. 

The CPU also connects to a seprate data RAM for memory reading and certain write operations. 

## Instruction encoding 

JH-8 uses an 8 bit instruction format 
|Bits| Field| Width|
|---|---|---|
|[7:4]|Opcode|4 bits|
|[3:2]|Destination register| 2 bits|
|[1:0]| Source register | 2 bits|

The  opcode determines the operation performed by the processor. 

Instructions that would require an additional immeditate value or memory address uses a second byte. The instruction decoder identifies these instructions and sets the insstruction length accordingly.

The decoder generates control signals for register writes, memory access, ALU operations, conditional jumps, flag updates and procesor halt. 

## Arithmetic Logic Unit 

The ALU is implemented inside of jh8_alu.v

It receives two 8-bit operands:

- Operand A: destination register data
- Operand B: source register data 

It produces an 8-bit result and status outputs. 

### Supported operations
|ALU control|Operations|Function|
|---|---|---|
|0x3|ADD|A + B|
|0x4|SUB|A - B|
|0x5|AND|A AND B|
|0X6|OR|A OR B|
|0X7| XOR| A XOR B|
|0X8|NOT|Invert A|

### Addition and subtraction implementation
The addition and subtraction circuits use explicitly expanded propagate and generate equations to calculate carry signals.

For addition: 
- Propagate signals are calculated using XOR.
- Generated signals are calculated using AND.
- Carry signals are expanded into Boolean equations. 
- The final result is generated using the operand propagate signals and calculated carries. 

Subtraction uses the complemented second operand and an initial carry of one, implementing two complement subtraction. 

This implementation makes the carry logic explicit in the RTL rther than relying on a simple arithmetic operator. 

### ALU status outputs 
The ALU generates: 
- **Zero**: Asserted when the result is zero. 
- **Negative**: Taken from bit 7 of the result. 
- **Carry**: Generated by the addition or subtraction carry logic. 

These outputs are connected to the processor's status flag module. 

## Registe file 
The register file is implemented within jh8_registers.v

It contains four general purpose registers: 
|Register|Width|
|---|---|
|R0|8bits|
|R1|8 bits|
|R2|8 bits|
|R3| 8 bits|

Each register is independently addressed using a 2-bit address. 

### Register file features
- Four 8 bit registers.
- Two independent combinational read ports. 
- One synchronous write port
- Independent write-enable decoding for each register
- Synchronous, active high reset. 

When reset is asserted on a rising clock edge, all four registers are cleared to zero. 

The two read ports allow the processor to obtain both ALU operands simulataneously. 

## Instruction ROM
The instruction memory is implemented within the jh8_rom.v file. 

The CPU connects the program counter to the ROM's  instruction address input. 

The ROM provides two outpus: 
- The instruction at the curernt program counter. 
- Immediate data at the address PC + 1.

This allows the CPU to retrieve the additional byte required for two byte instructions. 

The ROM initialization file is configurable through the ROM_INIT_FILE parameter of the CPU module, which defaults to the sim/program.hex file. 

## Data RAM 
The data memory is written in jh8_ram.v. 

It contains 256 bytes of storage, with an 8-bit address and an 8 bit data path. 

The RAM supports: 
- Memory reads through its read-data output. 
- Synchronous writes on the rising clock edge. 
- Write control through a memory wrie enable signal. 

The CPU uses the immediate data supplied by the ROM as the RAM address. 

For a memory write, the destination register's value is supplied as write data. 

For a memory read, the RAM output is selected by the writeback logic and cann be written into the destination register. 

## Processer status flag
The status flag module is implemented in jh8_flags.v. 


It stores three processor status flags
|Flag|Meaning|
|---|---|
|Zero|The most recent flag updating ALU result was zero|
|Carry| The ALU generated a carry output|
|Negative| Bit 7 of the ALU result was set|

The CPU supplies the ALU status outputs to this module. 

Flag updates are controlled by the decoder's flag_write signal and are disabled after the processor halts. 

The zero flag is used by conditional branch instructions. 

## Program counter 
The  program counter is inside f jh8_pc.v

It maintains the address of the current instruction and receives the next address from the CPU control logic. 

The next program counter value is selected between:
- Sequential execution: PC + instruction_length
- Jump execution: the immediate address supplied by the ROM 

The jump logic supports:
- Unconditional jumps. 
- Conditional jumps when the zero flag is asserted. 
- Conditional jumps when the zero flag is de-asserted. 

The program counter is enabled while the CPU is not halted. 

## Writeback datapath 

The CPU contains a writeback selection network that determines which value is written into the destination register. 

The 2 bit writeback_select signal selects one of four sources. 

|Selection|Writebback source|
|00|ALU result|
|01|Source register data|
|10|Immediate data|
|11|RAM read data|

The selected value is supplied to the register file's write-data input. 

This allows the processor to support ALU operations, register transfers, immediate loads and RAM reads through a shared register writeback path. 

## Instruction execution flow 

The JH-8 CPU uses a clocked execution architecture in which the instruction decoder and datapath generate the required control and data signals.

The general execution process is:
1. Instruction fetching: The program counter addresses the instruction ROM.
2. Instruction decoding: The decoder extracts the opcode and register fields and then generates control signals. 
3. Operand selection: The register file supplies the selected register values. 
4. Execution: The ALU performs the required arithmetic or logical operation when applicable. 
5. Memory Access: RAM operations use the immediate address supplied by the ROM.
6. Writeback: The writeback network selects the appropriate result for the destination register. 
7. Flag update: The status flags are updated when the decoder enables flag writing. 
8. Program counter update: The processor advances to the next instruction or takes a jump. 

The processor also supports a halt instruction. Once halted, register writes, RAM writes and program counter updates are disabled until it resets. 

## RTL module structure 
The main Verilog source files are organised as follows: 
|File|Description|
|---|---|
|jh8_cpu.v|Main CPU integration and datapath coontrols|
|jh8_alu.v| Arithmetic and logic operations|
|jh8_decoder.v|Instruction decoding and control generations|
|jh8_flags.v|Processor status flags|
|jh8_pc.v|Program counter|
|jh8_ram.v|Data memory|
|jh8_registers.v|General purpose register file|
|jh8_rom.v|Instruction memory|
|project.v|Project-level top module|

The design is separated into independent modules to make the processor easier to simulate, debug and develop. 

## Design verification 
NanoSilicon has been tested through RTL simulations, Tiny Tapeout design verification, and an ASIC implementation flow. 

### RTL simulation 
The integration testbench is located at:

sim/tb_jh8_cpu.v

The design is compiled using Icarus Verilog and simulated using vvp. 

The integration test has successfully demonstrated: 
- CPU instruction execution. 
- Register operations.
- RAM write and read behaviour. 
- Program counter progression. 
- Processor halt behaviour.
